# modplayjs-tracker-lib - Work Plan

## TL;DR (For humans)
<!-- Filled LAST - summarizes the REAL plan. Plain English, no file paths/todo numbers/stage jargon/tool names. -->

**What you'll get:** A browser library (TypeScript, built as a set of small local npm packages under the `modplayjs` name) that loads and plays the four classic tracker formats — MOD, S3M, XM, IT — with sound that tracks the reference players closely. It is fully pluggable: a small manager in the middle, one plugin per format, a shared set of common effects, a "Paula" sound engine (plus a standard mixer for the other three formats), and two ways to get audio out (live Web Audio and a downloadable WAV). A tiny demo page lets you drop in a file and play it so you can A/B it against XMPlay.

**Why this approach:** The whole thing is mirrored from the three reference codebases (OpenMPT, libxmp, Paula-Tracker) with no shortcuts — each format's quirks are ported, not guessed. Splitting it into per-format / per-effect / per-sound / per-output plugins means the manager stays small and new formats or effects can be added without touching the core. Two sound engines because the Amiga "Paula" sound only applies to MOD; the other three formats need the general mixer to be accurate.

**What it will NOT do:** No other tracker formats (big four only), no GUI or editor, nothing published to npm (all local for now), no automated test suite (you verify by ear against XMPlay), and no extra global effects like reverb/chorus that the references' core path doesn't use.

**Effort:** XL
**Risk:** Medium — the risk is fidelity detail (per-format quirks, IT's compressed patterns/NNA) rather than architecture; it's de-risked by porting line-by-line from the references and by the demo page giving you an immediate listening check.
**Decisions to sanity-check:** (1) Two sound engines (Paula for MOD, softmixer for S3M/XM/IT) rather than one; (2) verification is manual A/B against XMPlay with no automated tests; (3) npm workspaces monorepo (10 packages) even though it's local-only for now; (4) the project's own license is still TBD.

## Scope
### Reference precedence (binding for every todo)
1. **libxmp** — PRIMARY authority: player semantics, effects behavior, quirk flags, flow modes, per-format event readers, load-prologue defaults. All fidelity citations resolve to libxmp `src/` first.
2. **OpenMPT** — FILL-IN only where libxmp is thin or ambiguous: opcode translation cross-checks (`soundlib/MODTools.cpp ConvertModCommand`), format-variant parsing edge cases. Never overrides libxmp on player semantics.
3. **Paula-Tracker (`paulalib`) — DSP PART ONLY**: port its Paula mixing kernel + tables into dsp-paula (`audio-engine.js` linear-interp/loop-wrap channel sampler :769+, 0.7/0.3 pan ×0.5 clamp, `VIBRATO_TABLE`, period tables) and `encodeWAV` for out-pcm (`sampleutils.js:102`). Do NOT port its tick/row/effect sequencer (`processTick/processRow/processEffects`) — it's a simplified subset; MOD sequencing comes from the libxmp-mirrored Core.
### Must have
- **npm workspaces monorepo** under org `@modplayjs/*`, local-only (NO registry publish). Packages: `core`, `effects-shared`, `fmt-mod`, `fmt-s3m`, `fmt-xm`, `fmt-it`, `dsp-paula`, `dsp-softmixer`, `out-webaudio`, `out-pcm`, plus a `demo` app.
- **`@modplayjs/core`** — the manager: context + lifecycle (create/load/start/stop/destroy), per-frame loop + timing (frame/row/order/tempo/BPM), virtual-channel layer (voice mgmt, NNA/DCA), swappable sample store (on-demand hot-swap during playback), plugin registry, public API. Isomorphic (no DOM).
- **`@modplayjs/effects-shared`** — ONE shared-effects plugin: tracker effects that are identical across multiple formats (arpeggio, portamento, tone portamento, vibrato, tremolo, fine slides, finetune, volume slide/set, panning/pan slide, note cut, retrigger, position jump, pattern break, pattern loop, tempo/speed, sample offset), implemented as a **shared base + quirk hooks** (format plugins set quirk flags; shared effects branch on them).
- **`@modplayjs/fmt-{mod,s3m,xm,it}`** — ONE plugin per format, each containing EVERYTHING to play that format: parser (`test`+`load`), per-format event reader (`readEvent`), format-specific effects, and quirk flags. Ported near-perfect from the references (no simplified parts).
- **`@modplayjs/dsp-paula`** — Paula DSP plugin (for MOD): period-based pitch (`PAULA_FREQUENCY`), linear interpolation with loop wrap, 0-64 volume, fixed 4-channel pan (0.7/0.3), master ×0.5 + clamp. Ported from paulalib's mixing kernel ONLY (`audio-engine.js` `getChannelSample` :769+, pan/clip, `VIBRATO_TABLE`, period tables) — NOT its tick/row/effect sequencer (see Reference precedence).
- **`@modplayjs/dsp-softmixer`** — standard softmixer DSP plugin (for S3M/XM/IT): interpolation kernels (nearest/linear/spline), per-channel panning, volume scaling, multi-voice mix + downmix. Ported from libxmp `mix_all.c` + `mixer.c`.
- **`@modplayjs/out-webaudio`** — Web Audio output plugin using **AudioWorklet** (latest API): worklet processor pumps the engine on the audio thread; main-thread API sets up AudioContext + AudioWorkletNode.
- **`@modplayjs/out-pcm`** — PCM/WAV output plugin: accumulate rendered frames, encode 16-bit PCM WAV.
- **`demo`** — a Vite playback page (load a `.mod/.s3m/.xm/.it` → create player → play/stop). This is the verification vehicle for manual A/B against XMPlay.
- **Fidelity**: parsing AND playback near-perfect to the references (OpenMPT, libxmp, Paula-Tracker). No guessed/simplified DSP.
- **Strict TypeScript** everywhere (no `any`, no `@ts-ignore`), Vite build, Float32Array for all audio buffers.
- **Attribution**: LICENSE/NOTICE carrying the reference copyright notices (OpenMPT BSD-3, libxmp MIT © 1996-2026 Matsuoka/Carraro, Paula MIT).

### Must NOT have (guardrails, anti-slop, scope boundaries)
- NO other formats (no MTM, 669, MED, ULT, ST, etc.) — big four only.
- NO registry publish / no `npm publish` — local workspaces only.
- NO GUI / tracker editor — playback library + minimal demo page only.
- NO automated test harness / no C-reference build / no MD5 digest comparison / no numeric tolerance gate (verification is manual A/B vs XMPlay).
- NO Node.js output plugin (core stays isomorphic, but only webaudio + pcm outputs ship).
- NO WASM output, NO Web Audio `ScriptProcessorNode` (use AudioWorklet), NO `OfflineAudioContext` as the primary path.
- NO echo/reverb/chorus/global-FX DSP (not in the big-four references' core path; libxmp has none, OpenMPT's sounddsp global FX are out of scope).
- NO `any`, NO `@ts-ignore`, NO `as any`, NO empty `catch {}`.
- Must NOT copy reference code wholesale — port with structure mirrored, in strict TS.
- Must NOT bake decoded sample data into immutable per-format state (samples live in the core's swappable store; voices reference by ID).

- NO OPL/AdLib FM synthesis (S3M AdLib instruments: libxmp's core player silently DROPS these samples — `SAMPLE_FLAG_ADLIB` returns 0 without loading, sample.c:189-192; we mirror that behavior and don't build an OPL emulator).
- NO file depackers: packed archives (PowerPacker PP20, XPK, LZW/ICE, gzip wrappers) are OUT of scope — plain unpacked modules only; a typed `PackedModuleError` on a PP20/XPK/etc header is the documented boundary (libxmp wires these via `libxmp_decrunch`, reference/libxmp/src/load.c:152 + src/depackers/).
- NO hand-ported Vorbis codec: XM-embedded Ogg Vorbis samples decode via bundled WASM `stb-vorbis` (MPT export): decode via bundled WASM `stb-vorbis` (npm, Apache-2.0, sync `StbVorbis.decode(Uint8Array)` → planar Float32; matches libxmp's stb_vorbis use in loaders/vorbis.c) wrapped behind the core sample-store contract — NOT a hand-ported Vorbis decoder.
