T20 — out-webaudio: AudioWorklet processor (audio thread)
==========================================================
packages/out-webaudio/src/worklet.ts: ModPlayProcessor. Tight drain of a
render-ahead ring into outputs — no parsing/DSP on the audio thread
(replaces ScriptProcessorNode, audio-web.js:25-50; render drive via
playBuffer, player.c:2178-2233). Two transports:
- 'sab': lock-free ring over SharedArrayBuffer. Int32 header
  [writePos (main), readPos (audio)] monotonic frame counters;
  Float32 data interleaved stereo. Drains min(need, available) frames
  with modular wrap, publishes readPos via Atomics.store, zero-fills
  the tail on underrun (no NaN, no crash).
- 'copy': main thread posts transferable Float32Array chunks; internal
  ChunkFifo drains them; underrun → silence.
Ambient AudioWorkletGlobalScope declarations (AudioWorkletProcessor,
registerProcessor, sampleRate/currentFrame/currentTime) are declared
with real types — lib.dom/lib.webworker (TS 5.x) ship no worklet-global
types; nothing degrades to `any`. Registration is guarded so headless
node imports for testing work.

T21 — out-webaudio: main-thread AudioContext + AudioWorkletNode API
====================================================================
packages/out-webaudio/src/webaudio.ts: WebAudioOutput OutputPlugin.

AudioWorkletNode('modplay-processor', {numberOfInputs:0,
numberOfOutputs:1, outputChannelCount:[2]}) → connect(destination)

below HIGH_WATER = RING_FRAMES/2). start() is idempotent (no duplicate
nodes/loops). stop(): clear timer, disconnect node, suspend context.
audioContextSampleRate getter exposes the context rate for core config.
